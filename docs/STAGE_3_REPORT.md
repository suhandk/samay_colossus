# Stage 3 — farmer frontend

## Completed

First-visit Kannada/English selection with persisted preference; four-item mobile bottom navigation; separate settings; home with honest catalog state and saved-draft entry point; eight-step crop, mandi, quantity, quotation/reference, cash, storage, expenses and review form; individual section editing; explicit unknown costs; device-only draft snapshots, reopen and deletion. No registration or personal identity data is required. Draft saving is opt-in because inputs contain financial information.

Market prices retain actual API history, source/date/freshness and exact variety/grade selection. The chart loads as a separate route chunk. Forecasts remain explicitly unavailable. Added a central bilingual dictionary for the shell and guided workflow, shared date/currency formatters and device-voice detection. Existing market-page bilingual text remains colocated rather than migrated into the central dictionary. Kannada requires native-speaker validation. Speech works only if a matching installed voice exists; manual entry remains available.

PWA manifest, 192/512 icons and a versioned build-generated service worker cache only the app shell/assets. API requests are excluded. Offline warnings explain that data/recommendations cannot be verified. HTTPS or localhost is required for service workers; production deployment and physical Android installation remain untested.

## API integration and boundary

Catalog, coverage and history call real backend routes. Crop/mandi selection is constrained by observed backend combinations. The new POST /api/v1/recommendations route returns HTTP 503 with recommendation_engine_unavailable. It performs no calculation and returns no financial recommendation. The frontend shows the unavailable state, never an invented result. An actual recommendation engine, feasible strategy comparison, risks, acceptance and immutable saved recommendation history remain blocked. Saved items are labeled drafts, not plans generated by an engine.

Authentic market coverage is still empty from Stage 2. Four crop/six mandi cards appear only after verified registry configuration. No agricultural records were inserted for this frontend work. Isolated browser fixtures are used only in tests.
